# Резервное копирование и восстановление

Карантин не является резервной копией. Для полного восстановления нужны:

1. исходный фотоархив (`PHOTO_REVIEW_PHOTOS`);
2. карантин (`PHOTO_REVIEW_QUARANTINE`);
3. служебный каталог (`PHOTO_REVIEW_DATA`) с SQLite и миниатюрами;
4. файл `.env` или отдельно сохранённые значения конфигурации.

## Автоматическая копия перед миграцией

При первом запуске новой версии приложение определяет фактическую версию
существующей схемы. Если нужны миграции, до любых изменений создаётся
согласованная SQLite-копия:

```text
PHOTO_REVIEW_DATA/backups/
  photo-review-pre-migration-v3-to-v4-<UTC timestamp>.sqlite3
```

Копия создаётся через SQLite Backup API, поэтому включает зафиксированные
данные из WAL. После создания выполняется `PRAGMA integrity_check`. Новая пустая
база не копируется.

## Плановая резервная копия

Самый простой надёжный вариант для CasaOS:

1. остановить контейнер: `docker compose stop photo-review`;
2. скопировать три каталога, перечисленные выше, на другой физический носитель;
3. отдельно сохранить `.env` в защищённом месте;
4. запустить контейнер: `docker compose start photo-review`;
5. периодически проверять восстановление на тестовой копии.

Если контейнер нельзя останавливать, SQLite-файл нельзя копировать обычной
командой отдельно от `-wal` и `-shm`. Используйте SQLite Backup API либо
файловый snapshot всего тома. Автоматическая предмиграционная копия уже
использует безопасный API.

Фотоархив и карантин должны резервироваться как одна логическая версия: запись
в `audit_log` и расположение файла обязаны соответствовать друг другу.

## Восстановление после неудачного обновления

1. остановить контейнер;
2. сохранить повреждённый `PHOTO_REVIEW_DATA` для диагностики;
3. вернуть фотоархив и карантин к одной точке резервного копирования;
4. заменить `photo-review.sqlite3` проверенной копией;
5. удалить только перестраиваемый кэш миниатюр при необходимости;
6. запустить предыдущий совместимый образ;
7. проверить `/health`, список карантина и несколько операций восстановления на
   специально подготовленных тестовых файлах.

Не проверяйте восстановление на единственном экземпляре семейного архива.

## Проверка копии SQLite

На хосте с установленным `sqlite3`:

```text
sqlite3 photo-review.sqlite3 "PRAGMA integrity_check;"
sqlite3 photo-review.sqlite3 "PRAGMA user_version;"
```

Первая команда должна вернуть `ok`. Номер схемы не следует изменять вручную.
Программный откат миграции предназначен для тестовой копии; в рабочей
установке предпочтительно восстановление автоматически созданного backup.
